# 自由核心魔方：机器人单面接触转层开发（2026-11-03）

本阶段由用户要求“左手拿稳后开始扭魔方”触发。沿用已验收的反向腕弯、左掌朝右和肘外展 teacher，先将左手抓持迁移到真正可转层的模型，再由右食指推动朝向右手的 nZ 层。右手五指接抓 #2 仍未验收；本实验是单指接触路径，不代替该任务。

## 当前范围

- 原 9701–9705 的 5/5 是**锁层刚体**上的抓起、整块倾斜、保持。不能当作自由层模型或单面转动的成功率。
- 新环境包括自由核心和26个小块，重力开启、核心非运动学，使用原资产的内部关节。仅 reset 阶段初始化小块位姿；控制期间没有魔方位姿写回、关节驱动、外部推板或施加魔方力矩。
- 本轮全部使用开发 seed 9501。没有新增独立测试成功率、BC/PPO 更新或神经网络 checkpoint。
- 左手仍通过原安全层和 PD。右食指的整形、移动、接近、推转和撤回均先作网格避碰检查，再由 PhysX 真实接触验证。

合计5个完整开发尝试、1个中断尝试，均为已见 seed 9501、不同开发配置，没有独立成功率。90°未尝试；15°两次实际接触推转均未通过。第四轮实测片段为 `edge_push_clip.mp4`，无位姿回放或合成帧。

第五轮原始 `failure` 错误标为 `not_requested`，实际已经请求15°，是自由层抓持验收未通过；`dynamic_grasp_passed=false`、`assembled_hold_s=0`和未执行右手动作是正确的。保留原结果，归档中单独记录解释；后续入口已修正此报告标签，没有借此改变验收或重算为成功。

降低块间摩擦并未直接解决问题，也会改变抓持稳定性。所有材料参数是明确记录的仿真开发参数，尚未经过实物标定。手/魔方独立材料使用 PhysX `max` 摩擦合并，参考[官方合并模式说明](https://nvidia-omniverse.github.io/PhysX/physx/5.1.0/_build/physx/latest/struct_px_combine_mode.html)。输入 MJCF 的 `condim=1`、关节被动摩擦/阻尼与导入 USD 的参数对应关系仍需单独审计，不能把当前模型称为已校准的实物魔方。

## 接触轨迹修正

首轮接触点变换到实测右食指 DIP 坐标系后，与借用的左手镜像指腹点相差约15mm。`face_contact_calibration_v1.json` 保存实测点中位数、源轨迹/配置哈希和坐标定义。这是仿真开发标定。边缘推转使用该点，名义目标允许的网格侵入不超过2mm；机器人间隙3mm、非目标接触2mm和左手对旋转层1mm的检查保持开启。

先使用15°探测，不能据此宣称90°通过。右手实际接触必须来自食指末节、作用在nZ层，过早接触、接触错层、左手丢失、姿态越界、自碰、碰桌、掉落或限位命中会停止试验。

## 验收口径

`layer_turn_metrics.py` 对每个小块计算相对核心的旋转，不使用世界坐标转角。目标层九个小块各自的误差必须≤5°，非转轴偏差≤5°，其余小块转动≤5°，共同关节原点分离≤2mm。成功还要求撤回右手后连续3秒满足抓持、腕部、肘部、掌心和层姿态条件，并检查层角速度。中位转角只用于显示，不能单独晋级。

单面90°未通过之前，不开始两面连续转动、视觉蒸馏或PPO主线。无接触的 IK 预检通过不是物理成功。

## 运行

在已部署的 Isaac 6.2 / Lab 3 conda 环境中：

```bash
source /home/brainco/rl_cube/activate.sh
cd /home/brainco/rl_cube/revotron_cube_rl
./run_linux.sh face-turn --name UNIQUE_RUN --seed 9501 --contact-style edge --push-degrees 15 --friction .9,.8 --record
```

`--push-degrees 0`只做自由层抓持迁移；15/30为开发探测；90才是整面目标，应在小角度开发通过后使用。`face-turn`默认15°边缘探测，仍会先检查旧证书和当前回合抓持。旧`turn`保留为历史固定核心诊断入口，不作为新转层验收。一次只能运行一个 Isaac 进程。

离线网格预检目前使用本机 `/usr/bin/python3` 和 ROS Jazzy 的 Coal ABI；Isaac 和机器人控制仍运行在 conda 中。其他机器需要配置相应规划依赖，不能只安装 conda 包就假定可直接运行。

## 内部关节参数迁移缺口

静态审计 `asset_port_audit.json` 确认：输入 MJCF 的 cubelet 默认关节带有 `armature=0.0001`、`damping="0.0005 0.0005 0.0005"` 和 `frictionloss=0.001`；当前 `contact_test.py` 没有读取或映射这些属性。导出的 USD 有6个转动关节、20个球关节，仅对刚体设置 `angularDamping=0.2`，没有显式惯量补偿或上述被动关节参数。

这证明迁移参数不完整，**不证明它已被定位为当前失败的唯一原因**。MuJoCo 的 armature 表示关节附加惯量，具有影响数值稳定性的作用；新版 damping 多个数值可能表示速度多项式系数，不能未经版本核对就当作 XYZ 轴阻尼。参见 [MuJoCo 官方关节属性](https://mujoco.readthedocs.io/en/3.13.0/XMLreference.html#body-joint-armature)。后续应先核对上游版本、被动动力学和实际接触响应，再验证抓持与转层；不得用直接驱动魔方层角或关闭碰撞替代。
